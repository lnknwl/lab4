# Проектирование

**Описание**

Программа представляет шахматные фигуры на доске 8 на 8. Каждая фигура имеет цвет и позицию. Возможность хода определяется через виртуальный метод

**Поля базового класса**

| Поле | Тип | Назначение |
| --- | --- | --- |
| color | Color | Белый или черный цвет |
| x | int | Столбец от 0 до 7 |
| y | int | Строка от 0 до 7 |
| whiteCount | static int | Количество существующих белых фигур |
| blackCount | static int | Количество существующих черных фигур |

Все поля закрытые. Конструкторы и присваивание базового класса protected: их используют наследники. Изменять произвольную фигуру через присваивание базовой части извне нельзя

**Иерархия готовой работы**

```text
ChessPiece
├── SlidingPiece
│   ├── Rook
│   ├── Bishop
│   └── Queen + интерфейс CombinedPiece
├── JumpingPiece
│   └── Knight
└── King
```

В цепочках через SlidingPiece и JumpingPiece есть три уровня. Эти промежуточные классы абстрактные. CombinedPiece — отдельный интерфейс объединенного движения ферзя, без повторной базовой фигуры

**Условия корректности**

- Цвет — только White или Black
- Обе координаты находятся в пределах от 0 до 7
- Ход в текущую клетку не выполняется
- Неправильный ход сохраняет позицию
- Неудачный конструктор не меняет счетчики
- Копирование создаёт отдельную фигуру, присваивание не создаёт новый объект

**Виртуальные методы**

У `canMoveTo()` и `getSymbol()` нет общей реализации: они объявлены чисто виртуальными. Поэтому создать объект ChessPiece напрямую нельзя

`printInfo()` имеет готовую виртуальную реализацию. В наследниках она переопределена. Деструктор виртуальный, чтобы корректно удалять фигуры через ChessPiece*

`moveTo()` сначала проверяет границы, затем вызывает canMoveTo() нужного наследника. Если ход разрешен, меняет координаты

**Копирование и счетчики**

Конструктор копирования переносит цвет и координаты и увеличивает счетчик соответствующего цвета. Присваивание переносит данные в существующий объект. При смене цвета один счетчик уменьшается, а другой увеличивается

Деструктор уменьшает счетчик. При самоприсваивании данные сохраняются

Динамических ресурсов в базовом классе нет, поэтому копируются сами значения. Если в следующих классах будут контейнеры, их данные должны копироваться независимо

**Доска**

canMoveTo() отвечает за геометрию хода. Board учитывает занятые клетки и препятствия. Ладья, слон и ферзь не проходят через другие фигуры, конь может перепрыгивать

validateBoardState() находится в ChessPiece и принимает вектор указателей ChessPiece*. Она отклоняет пустые указатели, повторение указателей, совпадение позиций и более одного короля одного цвета

Пустые и неполные доски допустимы для демонстрации отдельных фигур. Наличие обоих королей не обязательно. Король представлен отдельным классом King

Board хранит указатели на внешние фигуры и не владеет ими. При взятии указатель убирается с доски, сам объект не уничтожается. Фигуры должны жить дольше доски. Подробнее: [Король и доска](board.md)

Полная шахматная партия с очередностью, шахом, матом и рокировкой в эту модель не входит
